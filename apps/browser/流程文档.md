# Chromium 内核编译流程文档
> 跨境防关联浏览器 · AntiDetect Browser 内核构建手册  
> 适用场景：短暂租赁的高配 Windows Server（64 vCPU / 256G RAM）

---

## 二、系统环境变量（永久写入，GUI 面板操作）

打开 `控制面板 → 系统 → 高级系统设置 → 环境变量`，在 **系统变量** 中编辑 `Path`，将以下内容**整体替换**（顺序不能乱，Git 必须在 depot_tools 前面）：

```
%SystemRoot%\system32;%SystemRoot%;%SystemRoot%\System32\Wbem;%SYSTEMROOT%\System32\WindowsPowerShell\v1.0\;%SYSTEMROOT%\System32\OpenSSH\;C:\Program Files\Git\cmd;C:\Program Files (x86)\Windows Kits\10\Windows Performance Toolkit\;C:\chrome\depot_tools
```

> ⚠️ **关键坑：`C:\Program Files\Git\cmd` 必须排在 `depot_tools` 前面！**  
> 否则 Python 会误调用 depot_tools 里的 git.bat 包装器，导致 `WinError 2` 崩溃。

新建以下系统变量：

| 变量名 | 变量值 |
|--------|--------|
| `DEPOT_TOOLS_WIN_TOOLCHAIN` | `0` |
| `vs2026_install` | `C:\Program Files\Microsoft Visual Studio\18\Community` |
| `GIT_CACHE_PATH` | `C:\chrome\git_cache` |
| `PYTHONUTF8` | `1` |

> ⚠️ **关键坑：新机器不要设置 `DEPOT_TOOLS_UPDATE=0`！**  
> depot_tools 在第一次运行时必须自我初始化（下载内置 Python、vpython 等）。  
> 若过早禁用 update，会导致所有 gclient 操作都报 `WinError 2 系统找不到指定的文件`。  
> 等 gclient sync 全部完成后，再根据需要设置此变量。

**修改完环境变量后，必须关闭所有终端并重新打开。**

## 三、模式 A：指定版本拉取（推荐，稳定可复现）

> 使用我们验证过的稳定版本 `147.0.7727.107`

```cmd
:: 进入工作目录（建议放在数据盘，不要放 C 盘桌面）
mkdir C:\chrome
cd C:\chrome

:: 1. 拉取 depot_tools（谷歌的构建工具集）
git clone https://chromium.googlesource.com/chromium/tools/depot_tools.git

:: 2. 精准克隆指定版本源码（--depth 1 只取最新快照，跳过几十G历史）
git clone -b 147.0.7727.107 --depth 1 https://chromium.googlesource.com/chromium/src.git

:: 3. 生成 .gclient 配置文件
cd C:\chrome
gclient config --unmanaged https://chromium.googlesource.com/chromium/src.git

:: 4. 同步所有 third_party 依赖（关键步骤，会下载额外的几百个子模块）
gclient sync --no-history --with_branch_heads --with_tags

:: 5. vs_toolchain 需要创建缓存目录
mkdir C:\chrome\git_cache
```

## 五、生成编译配置并编译

```cmd
cd C:\chrome\src

:: 创建 out\Default\args.gn 配置文件（直接写文件，避免 PowerShell 转义坑）
mkdir out\Default

:: 将以下内容写入 out\Default\args.gn（用记事本打开编辑也可以）
```

`out\Default\args.gn` 完整内容：
```gn
is_component_build = false
is_debug = false
symbol_level = 0
blink_symbol_level = 0
v8_symbol_level = 0
target_cpu = "x64"
dcheck_always_on = true

# ==========================================
# Ungoogled Chromium Flags (Anti-Telemetry)
# ==========================================
google_api_key = ""
google_default_client_id = ""
google_default_client_secret = ""
use_official_google_api_keys = false
enable_reporting = false
disable_fieldtrial_testing_config = true
enable_mdns = false
enable_service_discovery = false
enable_hangout_services_extension = false
```

> ⚠️ **256G 内存服务器使用 `is_component_build = false`（整体编译，速度最快）**  
> ⚠️ **32G 内存本地机器使用 `is_component_build = true`（切分小 DLL，防止 OOM）**

```cmd
:: 生成 Ninja 构建文件
gn gen out\Default

:: 开始编译（高配服务器不加 -j 限制，直接 64 核满载）
autoninja -C out\Default chrome

:: 本地低配机器请加限制防止内存溢出
:: autoninja -C out\Default chrome -j 6
```

## 六、补丁包工作流（本地改代码 → 服务器编译）

我们采用"本地动刀 + 服务器出货"模式：
- **本地机器**：我修改 C++ 源码，生成补丁文件
- **服务器**：负责 64 核暴力编译，输出 `chrome.exe`

### 生成补丁（在本地机器执行）
```cmd
cd D:\ai\canvas\apps\browser\chromium\src
git diff > ..\antidetect_v1.patch
```

### 应用补丁（在服务器执行）
```cmd
:: 将 .patch 文件复制到服务器的 src 目录下，然后执行：
cd C:\chrome\src
git apply antidetect_v1.patch

:: 打完针后直接增量编译（只重编被改动的几个文件，几十秒完成）
autoninja -C out\Default chrome
```

### 撤销补丁（回到干净状态）
```cmd
git apply -R antidetect_v1.patch
```

## 七、常见报错速查

### ❌ `WinError 2 系统找不到指定的文件`
**原因**：过早设置了 `DEPOT_TOOLS_UPDATE=0`，导致 depot_tools 未能完成首次初始化。  
**解决**：删除 `DEPOT_TOOLS_UPDATE` 环境变量，重新开终端运行 `gclient sync`。

### ❌ `LLVM ERROR: out of memory`
**原因**：编译并发数过高导致内存溢出。  
**解决**：加上 `-j 6` 限制并发数：`autoninja -C out\Default chrome -j 6`

### ❌ `Invalid token` 或 `Undefined identifier`（gn gen 参数报错）
**原因**：PowerShell 的转义机制吞掉了引号。  
**解决**：不要在 `--args` 里传参，直接写 `out\Default\args.gn` 文件，然后运行 `gn gen out\Default`。

### ❌ `lld-link: error: undefined symbol`（链接时找不到导出符号）
**原因**：新版本代码 + `is_component_build=true` 组合触发的已知 BUG。  
**解决**：将 `args.gn` 中的 `is_component_build` 改为 `false`，删除 `out\Default` 目录后重新生成。

### ❌ `GBK 编码错误`
**原因**：Windows 默认 GBK 编码与 Chromium Python 脚本不兼容。  
**解决**：设置 `PYTHONUTF8=1` 环境变量。
